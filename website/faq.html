FAQ

What this site can rebuild, how it differs from .srr files, and a few releases that show the difference.

What kinds of releases can be rebuilt?

  • RAR sets: single archives and multi-volume sets (.rar/.r00 and .partN.rar), from the 1994 DOS RAR 1.5x builds to RAR 7. That includes solid archives, recovery records, archive comments, authenticity blocks, and sets split differently per disc.
  • DOS-packed RAR sets: many late-90s and early-2000s releases were packed with DOS RAR. The app runs those original DOS builds under DOSBox-X, so the output matches to the byte.
  • ZIP releases: the original ZIP files, including their compressed data, headers and comments.
  • ZIPs that contain a RAR set: common for GP32, Gizmondo, iQue Player and N-Gage releases. The release is a ZIP holding a RAR (plus the NFO and DIZ), and the RAR holds the game files. Both layers are rebuilt: first the RAR from your files, then the ZIP around it. Example: Alien_Hominid_BETA_GIZMONDO_READNFO-SHiZMO, a ZIP holding shz-alho.rar, shizmo.nfo and file_id.diz, where the RAR holds 22 game files.
  • LHA archives (Amiga and DOS), packed again by the original LhA/LHA programs.
  • NFO, DIR and SFV fixes: releases that are only a few small files.

How is this different from srrdb and .srr files?

An .srr file stores the archive headers of a release. To rebuild, a tool such as pyReScene has to work out which WinRAR version and settings were used, by trying versions until a test piece matches. That works for many Windows-era releases. It can't run DOS RAR, it doesn't try every switch the scene used, and it doesn't cover ZIP or LHA.

An .rsr file records the answer: the exact archiver build and switches found when the release was captured. Every capture is checked by rebuilding it and comparing every volume with the original hashes, so nothing has to be searched for again later.

Do I need srrdb or an .srr file?

No. The .rsr has everything the rebuild needs except your own files. The app's srrdb Rebuilder also checks this site first, so a release that is here is rebuilt from its .rsr even when you start from srrdb.

Why does the app need old RAR versions?

A rebuild replays the archiver the group used, and different RAR builds produce different bytes from the same files. The Tools page lists every build, with hashes, and the app checks which ones you have.

What are the "Release files" downloads?

The small files that came with a release: NFO, SFV, DIZ and proof images. They can be downloaded on their own from each release page, including releases whose rebuild data is not hosted.

What do the numbers on the Progress page mean?

The Progress page counts every release in the dats.site scene DATs, one per game or set however many archive volumes it has, and shows how many can be rebuilt here, how many are listed only, which releases are damaged in the original upload, and which haven't been captured yet.
