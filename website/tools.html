Tools needed for rebuilding

An .rsr file says which archiver made a release and exactly how it was run. To rebuild the release, your PC needs that same archiver build.

Why so many RAR versions?

Different RAR versions, and even beta and bug-fix builds of the same version, produce different bytes from the same files. A scene group in 1998 used whatever RAR they had that week. To rebuild their archive byte for byte, the rebuild has to run that exact build. That's why full compatibility needs __N_WIN__ Windows/console RAR builds, from the 1996 RAR 2.00 beta to RAR 7.x, plus __N_DOS__ DOS RAR builds from 1994 onwards. The DOS builds run inside DOSBox-X, which the app manages for you.

ZIP releases are re-created with precomp. 7-Zip and UnRAR are used to read archives.

Where do I get them?

RAR builds are RARLAB's software and are not hosted here. Old WinRAR and RAR for DOS installers can still be found in software archives. You don't need to rename or unpack anything yourself:

  1. Put the installers or executables you found in one folder, with any names.
  2. In the app, choose Check packers → Import from folder.
  3. The app identifies each build by its SHA-256, including builds inside installers, and files it under the name it expects.

The check then lists anything still missing. A missing build only affects releases packed with that build. Every release page shows which packer it needs.

The full list

Every file the app looks for, with the SHA-256 it must match. A file with the right name but different contents is a different build, and the app reports it rather than using it.
