How it works
One run, two steps, the DAT is the only judge. Step 1 checks every .zip in the folder against the DATs and repairs the ones that differ. Step 2 matches each release folder to its DAT entry (by folder name, or by its archive names) and makes every .sfv/.nfo/.diz/.jpg the DAT lists right. A file is only written when its size, CRC32 and the DAT's MD5/SHA1 all match.
Fix in place (for a RomVault folder): a fixed file is written beside the wrong one and read back, then the wrong one is moved to the Backup folder (same sub-path, never overwriting an older backup) and the fixed copy takes its place. Nothing is deleted. Files that are already right are not touched. The default backup folder sits beside the folder, not inside it, so RomVault never sees the old copies as unknown files. Zips are fixed first, so an .nfo/.diz the DAT wants loose can then be taken out of the corrected zip.
Copy / Move: the folder is left as it is; every fixed or already-right file goes to Output\<release>\, with the release's other files that match the DAT (rar volumes and the like). In Move mode the originals are removed only after both steps have finished, so step 2 can still read the zips and loose sidecars step 1 used. Files that cannot be fixed always stay where they are.
Zip repairs, in order: the RSR store (a captured release rebuilds byte-exact) → a verified loose .nfo/.diz put into the zip → the real text of an edited .nfo/.diz → a sidecar the zip lost → the group's learned settings from reference zips → comment strip, truncation, line endings, junk removal, compression variants, faithful rebuild, heuristic junk removal, strip to essentials → foreign-packer diagnosis. Sidecar sources, in order: wrong copies in the folder, repaired → inside the release's own zip/rar/7z → the Extras folders → the RSR store and srrdb extras store → srrdb → a made .sfv (the DAT's CRCs in the group's own layout). A CSV report of the sidecar step goes to reports/.
